# AWS Auto Scaling Group (ASG) Questions 01

## Question 1
What is the primary purpose of an Auto Scaling Group (ASG)?

- A. To store application data
- B. To automatically add or remove EC2 instances based on demand or defined conditions
- C. To manage IAM permissions
- D. To route DNS traffic

<details>
<summary>Show Answer</summary>

✅ **Correct Answer: B**

An ASG automatically launches or terminates EC2 instances to maintain application availability and match capacity to demand.

</details>

---

## Question 2
Which of the following is required to launch instances within an Auto Scaling Group?

- A. A Launch Template or Launch Configuration
- B. An S3 bucket policy
- C. A Route 53 hosted zone
- D. A CloudFront distribution

<details>
<summary>Show Answer</summary>

✅ **Correct Answer: A**

An ASG needs a Launch Template (or the older Launch Configuration) that defines the AMI, instance type, key pair, security groups, etc. used to launch new instances.

</details>

## Question 5
What does "Desired Capacity" define in an ASG?

- C. The number of instances used only during scaling events

Desired capacity is the target number of running instances the ASG actively maintains, and it must stay between the min and max values.

## Question 6
Can the Desired Capacity be lower than the Minimum Capacity?

- A. True
- B. False

<details>
<summary>Show Answer</summary>

❌ **Correct Answer: B**

Desired capacity must always be greater than or equal to minimum capacity, and less than or equal to maximum capacity.

</details>

## Question 25
Which of these is a recommended ASG best practice for handling stateful data on instances?

- A. Store all application state locally on the instance's root volume only
- B. Design instances to be stateless, offloading persistent data to services like S3, RDS, or DynamoDB
- C. Disable scaling to avoid losing data
- D. Never terminate instances under any circumstances

<details>
<summary>Show Answer</summary>
