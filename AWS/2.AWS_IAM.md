# AWS IAM Questions 01

## Question 1
What does IAM stand for?

- A. Internet Access Management
- B. Identity and Access Management
- C. Infrastructure Access Model
- D. Internal Authentication Manager

<details>
<summary>Show Answer</summary>

✅ **Correct Answer: B**

IAM stands for Identity and Access Management — it controls who can authenticate and what they are authorized to do in AWS.

</details>

---

## Question 2
IAM is a global service, not tied to a specific Region.

- A. True
- B. False

<details>
<summary>Show Answer</summary>

✅ **Correct Answer: A**

IAM is global — users, groups, roles, and policies apply across all AWS Regions, not just one.

</details>

---

## Question 3
What is the AWS root user?

- A. A special IAM role for EC2 instances
- B. The account created when you first set up AWS, with full unrestricted access
- C. A default IAM group for administrators
- D. A read-only account used for auditing

<details>
<summary>Show Answer</summary>

✅ **Correct Answer: B**

The root user is created at account setup and has complete access to all resources — AWS recommends locking it down and using IAM users/roles for daily tasks.

</details>

---

## Question 4
Which of the following is a best practice regarding the AWS root user?

- A. Use it for all daily administrative tasks
- B. Share its credentials with the whole team
- C. Enable MFA and avoid using it for everyday tasks
- D. Delete it entirely

<details>
<summary>Show Answer</summary>

✅ **Correct Answer: C**

AWS recommends enabling MFA on the root account and using it only for account-level tasks that specifically require it.

</details>

---

## Question 5
What is an IAM User?

- A. A temporary set of credentials for an application
- B. A persistent identity representing a person or application that interacts with AWS
- C. A billing construct with no permissions
- D. A type of EC2 instance

<details>
<summary>Show Answer</summary>

✅ **Correct Answer: B**

</details>

## Question 6
What is an IAM Group used for?

- A. Grouping EC2 instances together
- B. Collecting IAM users to apply the same set of permissions to all of them
- C. Grouping S3 buckets
- D. Creating VPC subnets

<details>
<summary>Show Answer</summary>

✅ **Correct Answer: B**

IAM Groups let you attach a policy once to the group instead of repeating it for every individual user.

</details>

---

## Question 7
Can an IAM Group contain other IAM Groups?

- A. True
- B. False

<details>
<summary>Show Answer</summary>

❌ **Correct Answer: B**

IAM Groups can only contain users, not other groups — there is no nesting of groups.

</details>

---

## Question 8
What is an IAM Role?

- A. A permanent identity with a username and password
- B. A set of permissions that can be temporarily assumed by users, applications, or AWS services
- C. A billing alert mechanism
- D. A type of S3 bucket policy

<details>
<summary>Show Answer</summary>

✅ **Correct Answer: B**

An IAM Role is an identity with permissions that is assumed temporarily, rather than being tied permanently to one user.

</details>

- D. Naming an S3 bucket

<details>

## Question 11

- A. Full administrator access
- B. Read-only access to all services
- C. No permissions until a policy is attached

<details>
<summary>Show Answer</summary>

## Question 12
If a policy has both an explicit Allow and an explicit Deny for the same action, which takes precedence?

- A. Allow always wins
- B. Deny always wins
- C. It depends on the order in the document
- D. The action is undefined

<details>
<summary>Show Answer</summary>

✅ **Correct Answer: B**

In IAM policy evaluation, an explicit Deny always overrides any Allow.

</details>

---

## Question 13
What are the two types of IAM policies based on how they're attached?

- A. Managed policies and Inline policies
- B. Public policies and Private policies
- C. Static policies and Dynamic policies
- D. Root policies and User policies

<details>
<summary>Show Answer</summary>

✅ **Correct Answer: A**

Managed policies are standalone and reusable (AWS-managed or customer-managed), while inline policies are embedded directly into a single user, group, or role.

</details>

---

## Question 14
What is the difference between an AWS Managed Policy and a Customer Managed Policy?

- A. There is no difference
- B. AWS Managed Policies are created and maintained by AWS; Customer Managed Policies are created and maintained by the account owner
- C. Customer Managed Policies can only be applied to the root user
- D. AWS Managed Policies cannot be attached to roles

<details>
<summary>Show Answer</summary>

✅ **Correct Answer: B**

AWS Managed Policies are predefined by AWS for common use cases; Customer Managed Policies are custom-built and controlled by the account owner.

</details>

## Question 15

## Question 23
What happens if an IAM user has no policies attached at all?

- A. They get full access by default
- B. They are denied access to all actions, since there is no explicit Allow
- C. They get read-only access automatically
- D. Their account is automatically deleted

<details>
<summary>Show Answer</summary>

✅ **Correct Answer: B**

By default, everything is implicitly denied unless there is an explicit Allow — so a user with no policies has no permissions.

</details>

## Question 24

- B. AWS Security Token Service (STS) via assuming a Role
- C. IAM Access Keys
- D. IAM Password Policy

<details>
<summary>Show Answer</summary>

✅ **Correct Answer: B**

AWS STS is used to generate temporary security credentials when a role is assumed, commonly used for federation and cross-account access.

</details>

## Question 25
Which of these is NOT a component you would define within an IAM Policy statement?

- A. Effect (Allow/Deny)
- B. Action
- C. Resource
- D. EC2 instance type

<details>
<summary>Show Answer</summary>

❌ **Correct Answer: D**

An IAM policy statement is made up of Effect, Action, Resource (and optionally Condition/Principal) — not an EC2 instance type.

</details>
